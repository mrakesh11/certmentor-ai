AWS Shared Responsibility Model Cheat Sheet

Core Concept

The AWS Shared Responsibility Model defines security responsibilities between AWS and customers:

  • AWS is responsible for "Security OF the Cloud"
  • Customer is responsible for "Security IN the Cloud"
Remember: AWS secures the infrastructure, you secure what you put in it.

AWS Responsibilities

  • Global infrastructure
  • Hardware, software, networking, and facilities
  • Physical security of data centers
  • Hypervisor & service platform
  • Patching underlying infrastructure
  • Service availability & SLAs
  • Managed service configuration

Customer Responsibilities

  • Data encryption & integrity
  • Identity & access management
  • Network traffic protection
  • Operating system configuration
  • Network & firewall configuration
  • Client-side data encryption
  • Server-side encryption

  • Data management
  • Identity & access management
  • Client-side data encryption
  • Resource access policies

Service-Specific Responsibilities

Compute Services (EC2, Lambda)

  • AWS: Infrastructure, hardware, host OS
  • Customer: AMI selection, updates, data, security groups, IAM

Storage Services (S3, EBS)

  • AWS: Infrastructure, durability, availability
  • Customer: Data encryption, bucket policies, object ACLs

Database Services (RDS, DynamoDB)

  • AWS: Database engine, patching, backups (if enabled)
  • Customer: Schema design, data encryption, IAM permissions

Network & Content Delivery (VPC, CloudFront)

  • AWS: Edge locations, infrastructure security
  • Customer: Network design, security groups, NACLs, SSL certificates

Key Memory Aids

PATCH: Patching responsibilities
  • AWS patches infrastructure and managed services
  • Customer patches guest OS and applications in IaaS
DATA: Customer always owns
  • Data classification
  • Access policies
  • Tenant isolation
  • Analytics/monitoring
ENCRYPTION:
  • Customer is always responsible for data encryption choices
  • Both client-side and server-side encryption options must be configured by customer

Exam Tips

  • When in doubt, data security, encryption, and access management are customer responsibilities
  • Physical infrastructure and availability are always AWS responsibilities
  • The more managed the service, the less responsibility for the customer
  • AWS Config, CloudTrail, and CloudWatch are customer responsibilities to configure and monitor
  • Network traffic protection applies to both AWS and customer but in different aspects
